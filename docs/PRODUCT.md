# 产品范围与验收草案

更新：2026-10-11。状态：规划中。已确认需求不代表已实现；验收条目均未执行。

## 产品目标

面向公司同事的 Windows 视频混剪工具，把 AI 视频前贴（A）与游戏广告主视频（B）批量组合，生成可用于广告投放的素材。用户通过可视化设置或自然语言提出规则，能够检查和修改计划，再批量导出。

目标是把重复工作自动化，并让过程可查看、可暂停、可恢复、可交接。广告平台是否接受成片、是否认定内容重复及投放效果，不由本工具的组合去重规则保证。

## 建议的第一版流程（待确认）

导入A、B、音乐 → 检查素材 → 设置前贴声音和字幕 → 输入规则或填写表单 → 查看并编辑计划 → 试听、预览样片 → 批量导出 → 查看成功/失败结果并保存历史。

AI只把意图转成明确规则。数量、历史排除和配对合法性由程序再次检查；不直接执行AI生成的脚本或命令。存在冲突时展示原因，不默默修改数量、允许重复或忽略指定次数。

批量设置可以覆盖到指定前贴。修改计划后需要重新检查，导出使用固定的素材配对和设置；中断继续不重新随机。

## 组合规则示例

20条A与500条B，在完全没有历史排除时最多有10,000种配对。生成1000条，可安排每条A50次、每条B2次，且配对唯一。

有历史记录后，可用配对减少，均匀分配可能无法严格满足。软件应显示可用数量和冲突，不以总量足够推断所有指定次数均可满足。

混用示例：A01指定200次，其余19条A分配剩余800次；B尽量均匀，每个配对不同。这里“尽量均匀”与“严格每条相同”的区别必须在计划中显示。分配范围、误差规则和无法满足时的交互尚未定稿。

同一A要求600个不同B、而候选B只有500条时，必须拒绝该计划并解释原因。历史排除可能让某条A可用的B少于500条。

## 历史与恢复建议（待确认）

- 本机按游戏区分历史；历史范围的最终定义待确认。
- 只有成功生成且通过基础完整性检查的正式成片记为已使用。预览不占用；失败可重试。
- 已排入执行队列的配对需避免本机并行任务重复选择；取消、失败与成功各有清晰状态。
- 删除输出文件不自动清除历史；历史可备份、恢复。是否提供带确认的清除功能待定。
- 素材改名或移动仍识别为原素材。内容相同文件、重编码文件、剪辑变体如何识别需另行定义。
- 每条结果记录A、B、音乐、字幕/声音设置、导出状态和文件位置，方便追查。
- 暂停停止启动新工作；是否等待当前成片完成、多久响应，需实测后确定。恢复沿用原计划。

## 第一版验收草案

| 编号 | 可观察的通过条件 | 当前边界 |
|---|---|---|
| A01 | 在无历史、素材合格的20×500任务中，计划生成1000个不同配对；严格均匀模式满足A各50次、B各2次。 | 仅计划验证，不必先导出1000条证明数学分配。 |
| A02 | 指定次数＋剩余均匀的规则得到可解释分配；无解时给出冲突，实际数量不偷偷改变。 | 先定义“严格”与“尽量”的规则。 |
| A03 | 重启软件后仍排除本机已成功使用配对；素材改名、移动不使原配对变为可用。 | 身份识别方案待定。 |
| A04 | 自然语言示例生成可编辑计划；含糊或矛盾要求被标明；用户修订后重新检查。 | 模型服务、费用与离线替代待定。 |
| A05 | 在代表性真实A上，字幕可修正并预览；成片字幕无明显裁切，实际时间与预览一致。 | 中文术语、文稿对齐及已有硬字幕需专门评估。 |
| A06 | 保留B原声音；A声音模式可试听。去旧音乐效果通过真实口播、音效、残留音乐的人工试听。 | 分离质量未验证；未通过不得宣称支持高质量保留。 |
| A07 | 连接位置无意外黑帧、画面停顿、明显音画错位或口播被意外截断。 | 效果和时长规则待定。 |
| A08 | 样片与正式输出采用同一处理规则；导出尺寸、帧率、编码和声音符合约定。 | 平台/码率/帧率尚未确定。 |
| A09 | 中断、退出、恢复后不重新配对；完成结果不重复导出，失败可单独重试。 | 使用可控故障与重启场景验收。 |
| A10 | 1000条代表性任务得到逐条结果，成功、失败、取消数与计划对齐；损坏素材不会使整个任务无结果。 | 在小规模稳定后再开展全量实测。 |
| A11 | 后台模式同时使用浏览器、常用剪辑软件时体验可接受；记录耗时与资源情况。 | 常用软件、操作场景及“可接受”阈值待用户明确。 |
| A12 | 在另一台实际同事电脑完成安装/解压、启动、样片输出、恢复与历史保存。 | 同配置不等于已通过跨机验证。 |

## 待定项

1. 第一版转场种类、画面与声音过渡是否分别设置，以及是否允许重叠缩短总时长。
2. 前贴随机音乐按前贴固定一次，还是每条成片重新分配；两者支持范围和默认值。
3. 前贴音频分离达不到要求时，是否接受保留原声或人工提供纯口播作为替代。
4. B完整换音乐功能的版本范围。
5. 在线AI服务是否允许、费用预算，以及素材/音频可否上传；尚未取得上传授权。
6. 输出平台、精确尺寸、帧率、码率、命名方式及历史按游戏分组规则。
7. 字幕文稿输入格式、对齐失败处理、字幕样式和已有硬字幕的处理方式。
8. 安装包或便携文件夹、更新方式、缓存清理和磁盘空间策略。

## 建议暂不纳入第一版（待确认）

视频内容理解与语义配对、自动投放、多机共享历史、多机分布式渲染、完整剪辑时间线。后续有实际需求再评估。
