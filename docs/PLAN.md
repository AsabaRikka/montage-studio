## 分阶段交付

| 阶段 | 目的与交付物 | 进入/完成条件 |
|---|---|---|
| P0 当前：规划 | 需求、待定项、使用流程、验收标准和交接入口。 | 用户审阅草案，决定第一版边界。 |
| P1 可行性验证 | 少量真实素材的拼接、字幕、音乐分离样片；质量/耗时/资源记录；技术取舍。 | 用户明确授权实验并指定素材；观看试听通过，或形成明确替代方案。 |
| P2 最小完整流程 | 导入→确定配对→预览→少量导出→本机历史，先能完成一个真实任务。 | 单次少量端到端流程通过；AI接入顺序可按方案调整。 |
| P3 批量可靠性 | 数量规则、历史排除、指定次数、失败重试、暂停恢复、后台处理。 | 先小批量故障验证，再20×500/1000条代表性任务实测。 |
| P4 同事交付 | 安装或便携版本、简明使用说明、备份恢复和跨机检查。 | 另一台真实电脑通过使用流程；未覆盖环境明确记录。 |

这些是工作边界，不是强制“一阶段一个对话”。任意时机都可换对话，但应留下本次状态、版本和证据。时间与费用等验证后估算。

## 建议的职责划分

- 操作界面：选择素材、编辑字幕/声音、查看计划与进度。
- 规则与配对：验证数量、分配次数、排除历史、固定计划，不依赖模型自由发挥来保证正确性。
- 媒体处理：探测素材、准备A/B、字幕与音频、生成预览和成片。
- 本机任务与历史：保存素材身份、计划、配对状态、结果，重启后继续。
- AI适配：将语言变成有限的规则格式；服务可替换，调用失败不破坏已有计划。

这些是代码职责，初期可以在同一个应用内实现，不意味着要拆成多个服务。

## 候选技术及选择依据

| 部分 | 候选 | 需要先验证 |
|---|---|---|
| 桌面界面 | Python＋PySide6；或网页界面＋本地桌面壳 | 预览/字幕交互、打包大小、维护成本；尚未拍板。 |
| 媒体引擎 | FFmpeg/ffprobe | 编码支持、转场输入规范、音画同步、实际导出速度。 |
| 语音识别 | faster-whisper本地方案；或允许后的在线服务 | 中文质量、6GB显存兼容、部署依赖；文稿对齐是额外问题。 |
| 音乐分离 | 评估现有分离模型或允许后的服务 | 口播与游戏音效保留、显存、许可、部署成本；目前没有合格证据。 |
| 本机保存 | SQLite候选，配合明确的计划和结果记录 | 历史身份、状态一致性、并行任务、备份恢复。 |
| 一句话规则 | 在线模型候选，保留表单操作作为建议替代 | 服务授权、结构校验、费用、错误恢复；视频不必上传以完成规则解析。 |

## 设备与性能

2026-10-11通过本机只读查询确认：Intel i5-12400F，6核12线程；内存约15.8GB；GTX 1660 SUPER，6GB显存。磁盘剩余空间当时约C88.8GB、D349.5GB、E225.2GB；这些余量会变化，不是长期保证。

NVIDIA官方支持表包含该卡的硬件编码能力；项目未测试任何编码链路。faster-whisper项目中的性能数据来自其他硬件，不能当成本机速度。

建议默认后台模式，并提供全速和暂停。控制同时任务数、复用准备结果、适当降低任务优先级；没有实测前，不设虚假的CPU/显存上限或速度承诺。低优先级也不能保证显卡和磁盘不影响其他软件。

缓存按源素材与处理设置复用：同一前贴字幕不在1000条成片中重复识别；同一音频处理设置不重复分离。每条成片不同音乐时，应复用共同的口播处理部分，而不是把所有音频混合结果视为相同。

硬切可能采用准备后的片段复用路径；转场可能需要额外编码。是否能省去B重编码取决于编码参数、时间戳和拼接兼容性，不能仅凭尺寸相同作保证。

规划示例：1000×90秒×4Mbps÷8，输出约45GB（十进制），不含源素材和缓存。90秒与4Mbps均非最终输出标准；音画重叠、实际时长与码率会改变结果。

## AI编程的控制方式

每个工作任务写明：目标、允许修改范围、输入、验收方式、暂不处理事项。完成后由实际结果证明，并更新交接；不要求用户读懂所有代码。

开发准备时建立可恢复的版本记录。先做有限修改并验证，再扩展；不让模型同时重写界面、媒体引擎和历史逻辑。规则分配、去重、状态恢复适合自动测试；字幕观感、音频分离和后台体验必须人工检查。

更换模型依据任务与结果，不写死模型排行榜。调研、实现和审查可以使用不同模型，但都读取相同项目文件；额外审查只有在需要时进行，不默认开启大量代理增加费用。
