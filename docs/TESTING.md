# 测试分级

命名小更新用 `python main.py --quick-test test_results/naming_<版本> --naming-only`：独立合成媒体、旧云端标签描述显示、真实右键菜单/改名输入、共用规则设置、三种命名的实际720p一键导出及完整解码、高级计划命名快照、Qt播放解码、会话重开/恢复描述/历史身份保护。约半分钟；另跑 `tests/test_naming.py` 和相关云端纯逻辑/规则单测。发布只对最终EXE运行命名及数秒布局检查，不重复声音、字幕、网络下载或压力测试。报告必须全部通过且版本/EXE哈希一致，首轮失败报告保留并明确排除。

纯素材布局修复使用 `python main.py --quick-test test_results/layout_<版本> --layout-only`，只检查隔离合成卡片、三种窗口尺寸、A/B/云端真实鼠标勾选、末尾素材滚动、短窗口整页滚动、链接展开和保存位置窗口。源码检查约数秒；发布时对最终 EXE 再运行该入口。布局不涉及媒体处理时不重复云端下载、字幕识别、音频分离或长视频测试。小修复可交付独立完整文件夹与基于指定旧版的小补丁，避免再次压缩全部依赖；必须记录补丁基线、文件哈希并验证补丁应用后的 EXE。

小改动按风险运行必要检查，不把每次源码修改都当作发布门禁。规则或缓存纯逻辑修改运行对应的 pytest 文件；素材页、一键流程或历史缓存按钮修改，运行对应的 Qt 验证和相关单元测试；媒体引擎、数据库迁移、云端访问、PyInstaller 或发布文件修改，才运行隔离的媒体/便携验证与 ZIP 门禁。

例如一键流程和缓存改动的快速检查：

```powershell
$env:MONTAGE_DATA_DIR = "$pwd/test_results/fast_data"
python -m pytest tests/test_safety.py tests/test_rules.py tests/test_workflow.py -q
```

快速检查不能证明最终 EXE、真实长视频、云端接口或第二台电脑可用。准备发布版本时仍须使用独立数据目录运行相应的源码验证、冻结 EXE 验证和交付包审计；项目根目录 `data` 不用于测试。
